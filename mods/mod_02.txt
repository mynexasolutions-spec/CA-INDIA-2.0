Rules 
• 
No manual Client ID entry. 
• 
No manual editing of Client ID. 
• 
Client ID must be unique. 
• 
Duplicate Client IDs must never be permitted.

Client ID should be controlled at the database/system level to prevent duplication. 
3. Personal Information 
The Personal Information section should contain the relevant personal/contact address details. 
Address – PIN Code / City Auto-Fetch 
Wherever an address contains a PIN Code, the following functionality is required: 
PIN Code 
When the user enters a valid Indian PIN Code: 
1. System should validate the PIN Code. 
2. System should automatically fetch the corresponding City. 
3. The City field should be populated automatically. 
4. The user should not need to manually type the City when the PIN Code is successfully recognised. 
Example 
PIN Code: 400706 
↓ 
City: Navi Mumbai 
If the PIN Code is invalid or not found: 
• 
Display an appropriate validation message. 
• 
Do not populate an incorrect City.

16. Client Login Credentials 
The Client Login Credentials section should manage the credentials associated with the client's portal account. 
Password Change Synchronisation 
If the client changes their password from the Client Portal, the corresponding password information/status in the 
Admin Portal should be updated automatically. 
Similarly, if an authorised administrator changes/reset the client password from the Admin Portal, the client should 
be able to use the newly generated/assigned password. 
Important Security Requirement 
The system should not store passwords in plain text. 
Instead: 
• 
Password should be securely hashed/encrypted according to the authentication architecture. 
• 
Admin should not have unrestricted access to the client's actual password. 
• 
If the business requirement requires an administrator to set/reset a password, provide a Reset/Set Password 
function. 
• 
If a temporary password is generated, it should be displayed only when appropriate and should not be 
permanently stored in readable form. 
• 
Password changes from the Client Portal and Admin Portal should remain synchronised at the 
authentication/account level. 
Password Status 
The Admin Portal may display information such as: 
• 
Password last updated 
• 
Updated by Client / Admin 
• 
Last password change date 
rather than exposing the actual password. 
The actual password should not be displayed as readable plaintext.
