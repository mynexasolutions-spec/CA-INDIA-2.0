## IN SCOPE

### A. Document Numbering tab (mockup p23; PDF text has no section for it)
- Table, one row per document type: Tax Invoice, Bill of Supply, Credit Note, Debit Note, Quotation, Delivery Challan.
- Columns: #, Document Type, Prefix (e.g. INV, BOS, CN, DN, QUO, DC), Separator (e.g. `-` or `/`, user can enter their own), Next Number, Prefix Position (Prefix First / Prefix Last), Numbering Type (Auto / Manual), Number Format (Preview) e.g. `INV-01`, Status (Active toggle), Actions (View Sample).
- Side panel "Format Preview": pick a document type, show the formatted number and "Next number will be ...".
- Rules shown in the mockup: Auto = number increments automatically after each document is generated. Manual = user enters the number when creating the document. Prefix, separator, next number and position can be edited at any time.
- Edit / Save / Cancel as in 2A.
- Safety: see OPEN QUESTION 1 (duplicate numbers).

### B. Layout tab (PDF s17, mockup p25)
- Text: "Select a layout and colour that will be used for all invoices and documents generated for this client."
- 4 templates: Layout 1 Modern Professional (Top Header Style), Layout 2 Clean & Simple (Classic Corporate), Layout 3 Structured & Detailed (Table Focused), Layout 4 Modern Boxed (Panel Style). All 4 are delivered.
- 6 colour schemes: Slate Blue, Charcoal Grey, Dusty Plum, Mocha Brown, Deep Teal, Antique Gold. (Forest Green and Burgundy in the Configuration mockup are NOT part of the list.)
- Layout selection, colour selection, Preview, Current Selection (Layout, Colour, Active, Applied From, Last Updated), Edit, Save Changes, Cancel.
- Preview: static PNG placeholder until section F is built, then the real renderer with sample data ("View Full Size" opens the larger preview).
- Saving a new default here OVERWRITES the layout and colour of ALL rows on the Configuration tab. Before saving, show a confirm popup ("This will reset the layout and colour of all document types"). Cancel keeps everything unchanged.
- Retain the approved design in the mockup. Do not redesign.

### C. Configuration tab (PDF s18, mockup p26)
Document Layout Settings, per client and per document type:
- Rows: Tax Invoice, Bill of Supply, Credit Note, Debit Note, Quotation, Delivery Challan.
- Each row: Layout Template (dropdown), Colour Scheme (dropdown, the 6 colours), Preview (static).
- Data model: `client_id + document_type -> layout_id + colour_scheme + watermark_applies (yes/no)`. Rows can differ per document type.
Watermark Settings:
- Show Watermark ON/OFF, Watermark Text (e.g. `www.abkhanassociates.com`), per-document Yes/No, Preview (static).
- The text is later rendered as "Generated by <text>" in the document footer. Only storage in this module.
GST Return Reminder:
- Enable toggle ON/OFF only. NO Preview button (it is only in the mockup, not in the PDF text).
- Info note from mockup: "Reminder will continue until the filing request is submitted."
- Edit / Save Changes / Cancel as in 2A.

### D. Subscription (PDF s19, mockup p27)
- Subscription Details: Status * (dropdown, red dot when Inactive), From Date, To Date, Total Fees, Amount Paid, Amount Receivable, Outstanding.
- Inactive: Total Fees, Amount Paid, Amount Receivable, Outstanding all display as 0. Client data stays available. Red alert box: "Subscription is inactive for this client. No paid services are enabled. Client record is maintained for data management purposes only." Info note: financial fields are zero while inactive and client data is retained.
- Usage panel: Documents (count), Storage Used. See OPEN QUESTION 3.
- Save shows the success popup (2A).

### E. Service Access (PDF s20, mockup p27)
- Table: Service, Access (toggle), Remarks.
- Client Data Management: always ON. Remark "Always enabled for all clients".
- Billing, Document Change, Requests, GST Compliance, Reports: OFF and disabled when the subscription is inactive. Remark "Not Applicable (Subscription Inactive)".
- Display only unless OPEN QUESTION 4 says otherwise.

### F. Document templates (rendering): 4 layouts x 6 colours
- Render the 6 document types with the layout, colour and watermark chosen for that client and document type on the Configuration tab (default: Layout tab selection). This applies wherever documents are previewed, printed or turned into PDF.
- Source of truth: the reference pages (sample Tax Invoice, 4 layouts x 6 colours). Build ONE layout at a time in this order: Layout 1 (Modern Professional, Top Header Style), Layout 2 (Classic Corporate / Clean & Simple), Layout 3 (Structured & Detailed, Table Focused), Layout 4 (Modern Boxed, Panel Style). After each layout STOP so the user can compare it with the reference.
- Colours are theme tokens (CSS variables or a theme object). ONE structure per layout, 6 themes. Never build one template per colour. Sample the 6 colours from the reference pages.
- One template serves all 6 document types. Only the title, labels and the fields that really apply differ (e.g. no tax columns on a Bill of Supply). Reuse the data fields the app already has for each type, list the differences you find, and do not invent fields.
- Watermark: when Show Watermark is ON and the document type is set to Yes, show "Generated by <Watermark Text>" in the document footer (confirm against the reference).
- Preview eyes in the Layout and Configuration tabs use this renderer with sample data. The sample data comes from the existing billing/preview data if any, otherwise a fixed demo company/invoice.
- Clients with no saved config: see OPEN QUESTION 5.
- Do not break the current invoice output while building (feature-flag or fallback until the new renderer is verified).

Needs lead if no existing rule.
2. Inactive subscription: amounts stored as 0 or only displayed as 0 (history preserved)?
3. Usage panel (Documents count, Storage Used): where do these numbers come from today? If storage is not tracked, show the Documents count and a placeholder for Storage.
4. Does Service Access actually gate features (billing, requests, etc.) or is it display-only for now?
5. Fallback for clients with no saved layout/colour (existing clients): keep today's look, or default to Layout 1 + Slate Blue? Proposal: Layout 1 + Slate Blue as the saved default for every client (matches the Layout tab "Current Selection"), with the current look kept only until section F is verified.
6. Rendering approach today (HTML print vs PDF library) and whether the renderer is shared between admin preview, client portal billing and PDF download. Reuse it, do not create a second pipeline.
